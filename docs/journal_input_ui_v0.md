# 仕訳入力UI 設計 v0

前提: 企画設計書3-2「仕訳の操作UI」。採点ロジックは `yourwish_kentei` v0.3.0 の
`JournalLine`・`JournalAnswer`・`judgeJournal` を使う（実装済み・PR#3でマージ済み）。
本書はその上に乗るFlutter UIの設計。

## 1. 画面構成（上から）

```
┌─────────────────────────────┐
│ 問題文（prompt）                │
├─────────────────────────────┤
│ 貸借バランス表示（BalanceIndicator）│ ← 入力のたびに更新
├─────────────────────────────┤
│ 仕訳入力テーブル（JournalInputTable）│
│  借方科目｜借方金額｜貸方科目｜貸方金額 │
│  [行1]                          │
│  [行2] …                        │
│  [+ 行を追加]                    │
├─────────────────────────────┤
│ テンキー（NumericKeypad）         │ ← 金額セル選択時のみ表示
│  または                          │
│ 科目リストボックス起動ボタン         │ ← 科目セル選択時
├─────────────────────────────┤
│ [答え合わせ]                     │
└─────────────────────────────┘
```

科目セルをタップすると `AccountPickerSheet`（ボトムシート）が開く。金額セルをタップすると
下部がテンキーに切り替わる（システムキーボードは出さない）。

## 2. ウィジェット構成

### 2-1. `JournalInputTable`
- 行＝複合仕訳の1行。各行は `JournalLineInputCell`（科目セル＋金額セル）×2（借方・貸方）
- セルの状態: `idle` / `selected`（タップ中） / `filled`
- 行の追加・削除（複合仕訳。最低1行、上限は暫定5行）
- タップしたセルは自動でハイライトし、入力完了で次のセル（同じ行の反対側 → 次の行の借方）へ
  フォーカスを進める（企画設計書3-2「自動で次のセルへ進む」）
- Undo/Redo（直前の操作を1手戻せる。企画設計書3-2「誤タップの取り消し」）

### 2-2. `AccountPickerSheet`（ボトムシート）
- 絞り込み検索（かな・部分一致）を上部に固定
- 「最近使った科目」セクション（端末内、直近5件程度）
- 5要素（資産・負債・純資産・収益・費用）のグループ見出し。色は分野色ではなく中立色
  （科目の色は資格テーマ色と独立。グループ見出しにはアイコン＋文字ラベルを併記し、
  色だけに頼らない）
- 選択候補は `ExamConfig` 側の出題区分表の科目一覧（`docs/accounts_draft_v0.md` が
  仮案。公式確認後に確定）に限定する（出題区分表にない科目は出さない）
- タップで選択 → セルに反映 → シートを閉じて次のセルへフォーカス

### 2-3. `NumericKeypad`
- 0〜9、`000`（3桁一括）、桁区切り（カンマ）はリアルタイム表示、⌫（1文字削除）、C（クリア）
- 入力確定は「次へ」ボタンまたは次セルタップ。Enter相当のキーは置かない（誤操作防止）
- セルの下に固定表示。システムのソフトキーボードは一切出さない（画面を隠さない）

### 2-4. `BalanceIndicator`
- 借方合計・貸方合計をリアルタイム表示（`JournalAnswer`/入力中データから計算。採点とは別に
  UI側でも貸借合計だけは都度計算する）
- 一致なら✓＋「貸借が一致しています」、不一致なら差額を表示（色だけに頼らず文言必須）
- これは「正誤」ではなく「貸借が合っているか」のヒントのみ。正誤判定は「答え合わせ」を
  押すまで出さない（企画設計書3-2の区別を厳守）

### 2-5. 答え合わせ・誤り表示
- 「答え合わせ」を押すと `judgeJournal(correct, userInput)` を呼び、行ごとに
  `JournalLineDiff.kind` に応じた表示:
  - `correct`: ✓（緑系）
  - `wrongAccount`: 科目が違う旨＋正解の科目名
  - `wrongAmount`: 金額が違う旨＋正解の金額
  - `sideSwapped`: 「貸借が逆です」
  - `missing`: 「この仕訳が足りません」（正解側の行を薄く表示）
  - `extra`: 「この行は不要です」
- 色だけに頼らず、✓／✕アイコンと文言を併記（共通デザイン仕様どおり）

## 3. 状態管理

- `flutter_riverpod` で `JournalInputController`（`StateNotifier` または `Notifier`）
  - state: `List<JournalLineInput>`（各行: 借方科目・借方金額・貸方科目・貸方金額の入力中の値。
    未入力は null 許容）、`selectedCell`、履歴（Undo用）
  - `JournalLineInput` → 確定時に `yourwish_kentei` の `JournalLine` に変換して
    `judgeJournal` に渡す
- 手本: `bike` の `viewmodels/providers.dart` 構成（Riverpod Notifierパターン）に揃える

## 4. 実装の置き場所（決定: まず `ukalab-boki3` 側）

共通基盤ガイドの方針（表UI・テンキー・リストボックスは `yourwish_kentei` に汎用部品として
置き、2級や他の会計系資格でも使う）は維持するが、`yourwish_kentei` はこれまで純Dart
（UI無し）で、UI部品を追加すると初めてFlutter依存が入り影響範囲が大きい。そのため
**まず `ukalab-boki3` 側（`lib/journal_input/`）に実装し、動作を確認してから、
共通化（`yourwish_kentei` へのUI部品追加PR）を検討する**。

| 部品 | 置き場所 | 理由 |
|---|---|---|
| `JournalLine`/`JournalAnswer`/`judgeJournal` | `yourwish_kentei`（実装済み） | 採点ロジックは試験エンジン側 |
| `NumericKeypad`・`AccountPickerSheet`・`JournalInputTable`・`BalanceIndicator` | `ukalab-boki3`（`lib/journal_input/`、新規） | まずアプリ側で動かして固める。共通化は後続（他の会計系資格が着手する際に再検討） |
| 画面全体の組み立て・問題文表示・結果画面 | `ukalab-boki3`（このアプリ） | アプリ固有のレイアウト |

## 5. アクセシビリティ・操作性

- タップ領域44pt以上（`UkalabTheme.minTapTarget`）
- 文字拡大200%でテーブルが崩れない（セルは固定幅でなく可変、長い科目名は省略＋全文はツールチップ/ダイアログ）
- ダークモード対応（`UkalabTheme`のパレットを使う。色の直書きをしない）
- タップの触覚フィードバック・正解時の短いSE/アニメーションは設定でオフ可
  （`MascotWidget`の「動きを減らす」設定と連動）

## 6. 未決・要確認

1. `yourwish_kentei` へのUI部品追加の是非・タイミング（Flutter依存が初めて入る影響範囲の確認）
2. 複合仕訳の行数上限（暫定5行）
3. 科目名が長い場合の省略表示ルール
4. 精算表・財務諸表の穴埋め（企画設計書3-2「決算の穴埋め」）も同じ`JournalInputTable`の
   仕組みで作れるか、別部品が必要か
5. 勘定科目一覧の確定（`docs/accounts_draft_v0.md` の公式照合待ち）
