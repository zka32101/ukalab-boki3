# 簿記2級 追加検討（結論: 別アプリ。このリポジトリでの実装は対象外）

当初README「スコープの方針」は簿記2級を**このアプリに含める**方針だった。本ドキュメントで
商業簿記・工業簿記の両方を検討対象にアーキテクチャの再利用性を調査した結果、2級は**別アプリ**
（別リポジトリ）にする方針に転換した（2026-10-10、ユーザー判断）。このリポジトリ（うかラボ
簿記3級）での実装は対象外。以下は転換前に行った検討内容で、別アプリを作る際の設計の出発点として残す。

## 1. 2級の試験構成（現行、2026年時点の一般的な解説ベース）

一次資料（商工会議所の公式出題区分表）は**未入手**。以下はWeb検索による一般的な解説の要約で、
実装時は公式資料で必ず裏取りが必要。

- 大問5問、試験時間90分、合格基準70%以上（3級と同じ仕組みで表現できる）。
- 第1〜3問が商業簿記（配点60）、第4〜5問が工業簿記（配点40）という二本立て。
  - 第1問: 仕訳（3級と同形式、3級より複雑な取引・勘定科目）
  - 第2問: 連結会計・株式会社の純資産など（帳簿・財務諸表の空欄埋めが中心）
  - 第3問: 決算整理・財務諸表作成
  - 第4問: 工業簿記の仕訳・原価計算の基礎
  - 第5問: 標準原価計算・直接原価計算（CVP分析）などの総合問題
- **残課題**: 2027年4月以降の2級出題区分表（暫定版）は、3級と同時に改定されているはずだが
  一次資料が見つかっていない。1級は紙の手形・小切手廃止＋新リース会計基準の変更が確認できたが、
  2級の変更内容（3級に移った論点〈定率法・固定資産の除却廃棄等〉の代わりに2級へ何が追加されるか）
  は未確認。実装着手前に必ず確認が必要。

## 2. 既存アーキテクチャの再利用性

### 2.1 そのまま使えるもの

- `QuestionType`（`choice`/`journal`/`worksheet`/`ledger`、`ukalab_core`）: 商業簿記の仕訳・
  帳簿・精算表はこの4型で表現できる。連結会計の空欄埋めや財務諸表作成も`worksheet`型（セル単位の
  表の空欄埋め）で対応できる見込み。
- `AccountDef`/`AccountGroup`（資産・負債・純資産・収益・費用）: 2級商業簿記の追加科目
  （例: その他有価証券、繰延税金資産・負債、のれん、非支配株主持分等）もこの5区分に収まる。
  `boki3AccountsLegacy`と同じパターンで`boki2Accounts`（2級追加分のみ）を追加する形が自然。
- `journal_input`・`ledger_input`・`worksheet_input`・`voucher_input`・`evidence_input`の
  入力UI一式: 型自体を拡張しないなら改修不要。`accountPool`切り替えの仕組み（旧区分表対応で追加済み）
  を使えば、2級用の科目プールを渡すだけで済む。
- `PracticeSession`・`judgeJournal`等の採点ロジック: 全行一致・部分点なしの方針は2級でも
  変える理由がない。

### 2.2 新規に必要になりそうなもの

- **工業簿記の入力UI**: 製造原価報告書・原価計算表は表形式なので`worksheet`型で対応できる見込みが
  高い。一方、標準原価計算の「シュラッター図」のような図形パズル的な出題形式は、既存の4型に
  収まらない可能性がある（最初は出題を避け、表形式の設問〈原価差異の金額を答える等〉に絞るのも
  現実的な選択）。着手前に過去問・サンプル問題で実際の出題形式を確認する必要がある。
- **`ExamConfig`の構造**: 現状`SubjectConfig`はexam全体で共通（3級は`q1_shiwake`/`q2_choubo`/
  `q3_kessan`の3科目固定）。2級は科目構成自体が別物（5科目、工業簿記という新ドメイン）になるため、
  同一`examId`に`level2_...`を追加する形は**そのままでは合わない**（詳細は4章）。
- **アセット読み込み層のexamId対応**: `lib/exam_data/exam_data_cache.dart`が
  `assets/exam/boki3.questions.jsonl`等のパスを直接ハードコードしている。2級を別アセットファイル
  （`boki2.questions.jsonl`等）にするなら、ここをexamId引数化する改修が先に必要。

## 3. 勘定科目・問題データの一次資料

- 3級と同じく、2級も商工会議所の公式出題区分表・標準勘定科目表が一次資料になる。**現時点では
  未入手**（README未決事項2「出題区分表の原本」と同じ制約）。
- 2級の問題データも3級と同じ方針（過去問の転載はせず自作・出題区分表ベースの例題のみ、
  `source`/`sourceRef`必須）を踏襲する。

## 4. ExamConfig・アセット構成の方針（検討）

既存の3級は`examId: "boki3"`に`level3_until_2027_03`/`level3_from_2027_04`という2つの`levelId`を
持たせ、同じ科目構成（q1〜q3）のまま配点だけ変える設計だった。2級は科目構成自体が異なるため、
下記2案を検討する。

- **案A: 別`examId`（`boki2`）にする（推奨）**
  - 長所: 3級の`ExamConfig`・問題データ・用語集を変更せずに追加できる。科目構成・配点ロジックが
    別物なので無理に共通化しない方が自然。`RecordsPage`・`ProgressSummaryCard`等の集計も
    examId単位で素直に拡張できる。
  - 短所: `exam_data_cache.dart`・`PracticePage`・`MockExamPage`等、今「boki3」1つを前提に
    ハードコードされている箇所をexamId引数化する改修が必要（ただし構造的には`ExamConfig`は
    元々1つのexamに複数levelを持てる設計なので、examId自体を増やすのは自然な拡張）。
- **案B: 同一`examId`に`level2_...`を追加する**
  - README冒頭の方針文はこちらを想定した書き方だが、調査の結果、科目構成（3科目→5科目＋新ドメイン）
    の違いが大きく、`SubjectConfig`がexam全体で共通という現在の設計とは相性が悪い。採用しない方が
    良さそうという結論（本ドキュメントでの変更点）。

### 4.1 アプリ名・ブランディング

2級を追加する場合、「うかラボ 簿記3級」というアプリ名・ストア掲載情報の扱いを検討する必要がある
（「うかラボ 簿記3・2級」への改名、または3級版はそのままで新規に2級版アプリを別途出す、等）。
これはビジネス判断であり、本ドキュメントでは選択肢の提示のみに留める。

## 5. 想定フェーズ分割（着手する場合）

1. **Phase 0（資料収集）**: 2級の出題区分表（2027年度版）一次資料の入手、過去問・サンプル問題で
   工業簿記の実際の出題形式（表形式か図形式か）を確認する。
2. **Phase 1（基盤）**: `exam_data_cache.dart`等をexamId引数化し、`examId: "boki2"`の
   `ExamConfig`・空の問題データで「2級を切り替えて開ける」状態を作る。
3. **Phase 2（商業簿記）**: 2級商業簿記の勘定科目一覧・問題データ（仕訳・連結・財務諸表作成）を
   既存UIで追加する。
4. **Phase 3（工業簿記）**: 工業簿記の勘定科目・問題データを追加する。表形式に収まらない出題形式が
   必要なら、その時点で新規UI型を設計する。
5. **Phase 4（UI統合）**: ホーム画面での級の切り替えUI、記録・進捗の級別集計、ストア掲載・
   アプリ名の扱いを決定し反映する。

## 6. 結論（2026-10-10時点、方針転換）

- 本章4節の検討（同一`examId`に`level2_...`を追加するより別`examId`にする方が整合するという結論）
  を踏まえ、ユーザー判断により**簿記2級はこのアプリに含めず、別アプリ（別リポジトリ）にする方針**
  に転換した。README冒頭の「スコープの方針」も合わせて更新済み。
- このリポジトリ（うかラボ 簿記3級）での2級実装は**対象外**。本ドキュメントの4〜5章の検討内容
  （`QuestionType`・`AccountDef`・入力UI一式の再利用性、ExamConfig構成の方針、フェーズ分割案）は、
  今後別アプリ（別リポジトリ）を作る際に`ukalab_core`・`app_common_kit`の共通エンジンをどう
  再利用するかの出発点として残す。
- 2級の出題区分表の一次資料・工業簿記の出題形式確認は、別アプリ側で着手する際に必要になる。
