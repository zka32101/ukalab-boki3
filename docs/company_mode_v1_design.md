# 会社経営モード 設計（v1・ドラフト）

## 出典・経緯

README「未決・要確認」6「会社経営モードの無料範囲、初回リリースに含めるか」に対応する企画。
2026-10-08、次の機能案の検討で「苦手科目→用語集連携」に続く拡張として着手。

ゲーム性の方向性と初回スコープはユーザーと確認済み：

- **ゲーム性: 仕訳ドリブン型**。毎ターン取引イベントが発生→その場で仕訳を入力させ、正誤が会社の
  財務諸表にそのまま反映される。既存の `journal`/`worksheet` 入力UIをほぼそのまま再利用でき、
  実装コストが低い（経営シミュレーション型のような新規ゲームロジック〈在庫・価格・需要〉は持たない）。
- **初回スコープ: 複数シナリオ**。業種違いの短いシナリオを複数本、初回から用意する。

## コンセプト

「問題を1問ずつ解く」演習・模擬試験とは別に、**1つの会社を立ち上げて数ターン経営する中で、
取引のたびに仕訳を入力する**ロールプレイ型モード。演習で覚えた仕訳の知識を、文脈（なぜこの取引が
発生したか）とセットで使う練習になる。最終ターンで累積の損益計算書・貸借対照表が完成し、
「経営の結果」として見せる。

決定49「推し」のような既存のモチベーション要素とは独立に、**仕訳の文脈理解**という学習効果を狙う。

## ゲームループ

1シナリオ＝固定ターン数（目安5〜8ターン）の直列進行。

```
シナリオ開始（会社名・業種・初期資本金の提示）
  ↓
ターン1: 取引イベント文の提示（例:「開業資金として現金50万円を元入れした」）
  → 仕訳入力（既存の JournalQuestionView を流用）
  → 正誤判定・解説表示（既存の judgeJournal・JournalResultBanner を流用）
  → 不正解でも「正しい仕訳」で強制的に帳簿へ反映し、次ターンへ進む
    （ここで詰むとゲームが止まってしまうため。不正解は記録だけ残す）
  ↓
ターン2 〜 最終ターン-1（同様に繰り返す）
  ↓
最終ターン: 取引なし。これまでの仕訳を集計した貸借対照表・損益計算書を表示
  ↓
結果画面（正答率、資本の増減、「経営成績」のラベル表示）
```

演習・模擬試験と違い、**1シナリオを通して1つの会社の帳簿を作り続ける**のが差別化点。

## データモデル設計

### 置き場所: `yourwish_kentei`（全アプリ共通ライブラリ）

既存の決定（`yourwish_kentei` にアプリ非依存のゲームロジックを集約する）に従う。「シナリオ×取引×仕訳」
という型は簿記以外の検定（乙4・AI検定等）でも「手続きを順番に正しく行うロールプレイ」として転用できる
可能性があるため、`yourwish_kentei/lib/company_mode/` に置く。ukalab-boki3 側はシナリオデータ（JSONL）と
画面のみを持つ（用語集と同じ分担方針）。

### モデル案

```dart
/// 会社経営モードの1シナリオ（業種・初期状態・ターンの流れ）。
class CompanyScenario {
  final String scenarioId;
  final String examId;              // 'boki3' など
  final String companyName;         // 「カフェどんぐり」等
  final String industry;            // 表示用の業種ラベル（「飲食業」等）
  final String introText;           // 開始時の導入文
  final int initialCapital;         // 初期資本金（円）
  final List<CompanyTurn> turns;    // 取引ターン（最終集計ターンは含まない。turns.length がターン数）
  final QuestionSource source;
  final String sourceRef;
}

/// 1ターン分の取引イベント。
class CompanyTurn {
  final String turnId;
  final String eventText;           // 「商品10万円を仕入れ、代金は掛けとした」等
  final JournalAnswer answer;       // 既存の JournalAnswer をそのまま使う
  final String explanation;         // 既存の解説表示（ExplanationWithTerms と同じ仕組みを再利用）
}
```

### 既存エンジンとの接続（新規ロジックは最小限にする）

- 1ターンの仕訳入力・採点は、既存の `JournalQuestionView`・`judgeJournal`・`JournalResultBanner` を
  **そのまま**使う（`prompt` に `eventText` を渡すだけ）。`explanation` も既存の `ExplanationWithTerms`
  がそのまま使えるため、解説中の用語集連携（決定: 2026-10-08）も自動で効く。
- 新規に要るのは次の2点のみ：
  1. **シナリオの進行管理**（`CompanyScenario` の何ターン目かを管理する軽量な `StateNotifier`。
     `PracticeSession` の最小版に近いが、「不正解でも正しい仕訳を帳簿に反映して進む」という
     演習にはない挙動が入るため、新規に作る）
  2. **累積財務諸表の集計**（各ターンの `JournalAnswer.lines` を順に適用し、勘定科目ごとの残高を
     積み上げて貸借対照表・損益計算書の形に整形するロジック。`judgeWorksheet` 相当の新規ロジックが
     必要になる見込み）

## 無料範囲・課金（READMEの未決事項への回答案）

- 初回リリースでは**全シナリオを無料公開**する（会社経営モードは差別化訴求の目玉のため、課金の壁に
  しない）。
- 将来、シナリオ数が増えた場合（決算整理を含む難しいシナリオ、業種追加）に一部を有料化する余地を
  残す。ただし初回3本は無料のままにする（無料ユーザーが機能の価値を体験できることを優先）。
- 決定5（無料枠の回数制限）の `UsageQuota`・`FreeTierLimits`（`yourwish_kentei`）をそのまま流用できるか
  どうかは Phase 2 で検討。

## フェーズ分割

- **Phase 1（MVP）**: `yourwish_kentei` に `CompanyScenario`・`CompanyTurn`・配信前検証を追加、
  シナリオ進行管理・累積財務諸表集計のロジック、ukalab-boki3側にシナリオデータ3本＋画面一式。
  「もう一度」「シナリオ選択に戻る」のみ（結果の保存・進捗記録はしない）。
- **Phase 2**: 結果を `ProgressStore`/`ProgressRecord` と同様の仕組みで記録し、「記録」タブに
  経営履歴を表示。苦手科目連携（2026-10-08実装）と同じ発想で、経営中の誤答を用語集・復習導線に
  つなげる。
- **Phase 3**（2026-10-08実装）: 決算整理を含む本格シナリオを2本追加（法律事務所つくし〈サービス業・
  7ターン、貸倒引当金の設定と減価償却の2つの決算整理〉・卸売商事にじいろ〈卸売業・7ターン、借入・
  売上値引き・支払利息〉）。計5シナリオすべて無料で公開する（下記「有料化の検討」を参照）。

### 有料化の検討（Phase 3時点の結論）

企画段階では「将来シナリオ数が増えたら一部有料化の余地を残す」としていたが、実装に着手した段階で
見送ることにした。理由: アプリ全体でまだ課金導線（`isPremium` 判定・`FreeTierLimits`/`UsageQuota`
の適用）が一切実装されていない（模擬試験の回数制限・復習の日次制限など、他の無料枠も未適用）。
この状態で会社経営モードだけ先行して課金ゲートを作ると、アプリ全体の無料/プレミアムの線引きと
矛盾する。アプリ全体の課金導線を実装する段になったら、そのタイミングで
`FreeTierLimits`（`yourwish_kentei`）に「無料で遊べるシナリオ数」のような制限を追加し、
シナリオ一覧の後半をロック表示する方針で検討し直す。

### 有料化の実装（2026-10-10、Phase 4）

別セッションの統合で、アプリ全体の課金導線（`purchases_flutter`・`entitlementServiceProvider`・
`PremiumFeature`〈弱点ドリル等〉）が実装された。これにより「アプリ全体の課金導線を実装する段」に
なったため、会社経営モードの有料化を実装した。

- 業種違いの最初の2シナリオ（カフェどんぐり・雑貨屋ことり）は無料のまま、残り3シナリオ
  （フリーランス事務所・法律事務所つくし・卸売商事にじいろ）をプレミアム限定にした
  （`lib/company_mode/company_scenario_list_page.dart`の`freeCompanyScenarioIds`）
- `ukalab_core`（別リポジトリ）の`PremiumFeature`enumには、コメント上「問題・解説・模擬試験・
  基本の苦手特訓は無料でここには含めない」という共通方針があり、会社経営モードはまだ含まれていない。
  このセッションのGitHubアクセスは`ukalab-boki3`のみに限定されているため、共通enumは変更せず、
  アプリ側で`entitlementStateProvider`（`EntitlementState.hasPremium`）を直接見て判定する形で実装した
  （弱点ドリルの`PremiumFeature.weakDrill`とは別の線引き）
- 未購読でプレミアムシナリオをタップすると、画面には入らず案内（SnackBar）のみ出す
  （`weak_drill_card.dart`と同じパターン）。一覧では未購読でも鍵アイコンでロック中と分かるようにした
- `test/company_scenario_list_free_test.dart`・`company_scenario_list_premium_blocked_test.dart`・
  `company_scenario_list_premium_allowed_test.dart`で検証（既知の制約により1テスト1ファイルに分割）。
  `flutter analyze` 0件・`flutter test`（99件）成功
